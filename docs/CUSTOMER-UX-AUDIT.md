# Customer marketplace UX audit

Status: local code and production-build browser audit against synthetic D1 data, 2026-09-29. No production traffic or data was inspected. Screenshot samples are local artifacts in `/tmp/larkvine-ux`; they are not production evidence.

## Journey and prioritized findings

| ID | Severity | Evidence | Customer impact | Planned or implemented response |
| --- | --- | --- | --- | --- |
| UX1 | P1 | `SiteChrome` rendered Header and Footer before `<main>` in `src/app/layout.tsx`; browser screenshots at 390 and 1440 px placed the footer immediately after the header, then page content. | Every page starts with a footer before its actual purpose; navigation and content order are confusing for sighted and assistive users. | Compose Header → main → Footer in one shell. Implemented and locally browser-verified. |
| UX2 | P1 | Header exposes only icon buttons on desktop; Shop, Stores and Orders are inside a drawer (`Header.tsx`). Search is one tap away on every viewport. | New visitors cannot see the main marketplace paths immediately. | Desktop text links and a visible search field; mobile keeps compact controls with direct Shop/Cart access. No Wishlist link because no wishlist exists. |
| UX3 | P1 | `CartPage` renders all lines in one list, with a Store link per line but no seller grouping. `CheckoutClient` does the same. | A multi-vendor customer cannot tell which seller handles each part or why there are multiple WhatsApp contacts. | Group by store and explain separate seller fulfilment, keeping totals provisional and checkout authoritative. |
| UX4 | P1 | Checkout opens each vendor WhatsApp window automatically after order creation; confirmation creates a WhatsApp CTA even when a store has no contact number (`href="#"`). | Popup blocking or missing contact can leave the next step unclear. | Keep customer on receipt and offer valid seller contacts there; show a support path if contact is absent. Explicitly state payment is arranged manually and unverified. |
| UX5 | P1 | `HeroSection` calls a capped `allProducts.length` value total “Products to discover”; homepage merges store-local categories by name and calls `featured` Products “Trending” (`src/app/page.tsx`). | Inaccurate counts and implied popularity mislead users; same-named local categories may differ. | Remove unsupported counts/category grouping; label curated featured products accurately; keep concise discovery paths. |
| UX6 | P1 | At 768 and 1024 px, every customer route had horizontal document overflow; DOM measurement traced it to the footer email span (`Footer.tsx`). | Tablet users must scroll sideways. | Allow the contact address to break within its grid column. Implemented; local recheck at 320/375/390/430/768/1024/1440 px found no document overflow on home, catalog, Store directory, product, empty Cart/Checkout or anonymous Orders. |
| UX7 | P2 | `/shop` places all filters in a large always-visible grid before products; on phones this makes browsing start several screens down. | Discovery requires excessive scrolling; active filters are hard to see. | Compact toolbar, mobile disclosure/drawer and active-filter summary while retaining URL-backed server filters. |
| UX8 | P2 | Product cards show name, price, store, description, precise stock and full-width button (`ProductCard.tsx`); gallery and cards use `unoptimized` R2 images. | Cards are tall and dense on small phones; original images can be oversized. | Reduce to image/name/price/store and truthful low-stock cue; verify image delivery before switching optimization. |
| UX9 | P2 | Product detail starts with gallery and long description before purchase controls; mobile has no convenient persistent CTA (`ProductDetails.tsx`). | Mobile buying action may sit below the fold. | Reorder description below options/CTA and add a mobile purchase control only after browser testing. |
| UX10 | P2 | Account history has useful seller grouping but dense text and no status timeline; guest history is intentionally unavailable (`account/orders/page.tsx`). | Order progress takes effort to scan. | Improve status hierarchy and empty state without inventing payment verification or fulfilment tracking. |
| UX11 | P2 | Search overlay is an icon trigger, category suggestions navigate to Store home rather than that category (`SearchBar.tsx`). | Search takes an extra step; category suggestion intent is lost. | Keep category suggestions store-scoped and link to the store category filter. Use a visible desktop search entry. |
| UX12 | P2 | Browser-rendered `/cart` and `/checkout` empty states use “Archive” or garment-only language (`CartPage`, `CheckoutClient`). | Copy conflicts with a broad marketplace. | Use “marketplace”, “products”, and clear manual-payment language. |
| UX13 | P2 | Store directory has reliable approved-store cards and bounded counts; no description, and its empty state invites the customer to sell (`stores/page.tsx`). | Buyers cannot distinguish stores quickly, and an empty buyer path ends in seller signup. | Add short public description and a buyer-oriented empty state. |
| UX14 | P2 | Menu and search overlays declare dialogs, but no focus trap or focus restoration is implemented (`Header.tsx`, `SearchBar.tsx`). | Keyboard navigation can escape behind an open overlay. | Add focus management and keyboard regression checks. |
| UX15 | P3 | Global CSS, `Button.tsx`, and pages mix pill and square buttons, multiple radii, bespoke border/shadow colors, and 10–13 px body text. | Visual hierarchy and touch affordances vary by page. | Reuse existing color/font tokens, simplify radius/shadow use and standardize focus/spacing incrementally. |

## Design system inventory

- Fonts: Noto Serif headings and Montserrat body via Next Font. Several components also use generic `font-serif`, producing a third apparent type treatment.
- Colors: primary green `#005C29`, gold `#D4AF37`, neutral line `#E5DDD3`, muted `#555555` in `globals.css`; pages also hard-code multiple creams/greens.
- Containers: mostly 1100–1200 px, with `px-4`, `px-6`, or `px-8` independently chosen.
- Buttons: shared `.cta-*` and `Button` duplicate similar pill styles; quantity controls are 32 px, below the desired 44 px tap area.
- Inputs: shared `Input` uses border-bottom fields; checkout duplicates its own field class and error text. Labels exist, but errors are not linked to fields.
- Cards and images: product, Store, cart, and receipt cards use unrelated 16–32 px radii and bespoke shadows. Product images reserve aspect ratios, reducing image CLS; optimization is bypassed.
- Loading/empty/error: meaningful shop and cart empty states exist; `Suspense fallback={null}` leaves blank regions on several server pages, and some error copy lacks a recovery action.
- Wishlist/reviews: no implemented customer wishlist or reviews. Do not add misleading navigation or trust metrics.

## Scope and limits

The local fixture has two approved Stores and sparse product imagery; it cannot validate real image quality, category semantics, ratings, delivery policy or conversion. Browser widths were rendered at 320, 375, 390, 430, 768, 1024 and 1440 px. The first pass found no document overflow on phone widths and found footer-induced overflow at 768/1024 px. Real checkout browser E2E is recorded separately in `AUDIT.md`.

## Implemented and verified locally

- UX1: `SiteChrome` now wraps page content between Header and Footer. Post-change screenshots at 390/1440 px show the marketplace hero before the footer.
- UX2: desktop Header exposes Shop, Stores, Orders, Account/Sign in and a labelled search entry. Mobile has direct Home, Shop, Orders and Account navigation; Search and Cart remain in the top bar. The navigation browser test checked desktop visibility, mobile menu Escape/focus restoration, search focus, and URL filter back/forward behavior.
- UX3/UX4: Cart and Checkout group items by seller. Checkout states that payment is arranged manually and no payment is confirmed. It no longer opens WhatsApp windows automatically; the receipt presents the seller actions. A missing WhatsApp number now leads to a support path instead of `href="#"`.
- UX5: homepage no longer labels a capped list as the total catalog, merges store-local categories, or calls vendor-featured items trending. It queries at most eight Stores, ten new Products and ten featured Products. The concise hero links to the global catalog and Store directory.
- UX6: footer contact text wraps. A post-change browser measurement at 320/375/390/430/768/1024/1440 px found no document overflow on the homepage, catalog, Store directory, product detail, empty Cart/Checkout, or anonymous Orders page (`documentWidth === viewportWidth` at every width, including product detail at 768/1024 px after its grid changed to fractional `minmax(0, …)` columns).
- UX7/UX8/UX11: mobile catalog filters are collapsed in a native details disclosure; active count and clear action are visible, with the existing shareable URL behavior preserved. Product cards now prioritize image, title, price and Store. Search category suggestions link to a specific store-scoped Category; pending searches are aborted when query changes.
- UX9: mobile gallery shows the main image before thumbnails, preserves image aspect ratio, and product description follows the purchase controls. A compact mobile Add to cart control sits directly above the bottom navigation; `scripts/verify-product-mobile.mjs` confirmed at 390 px that it is fixed above the nav (within 1 px of the nav top), stays fixed while scrolling, that a tap adds the fixture product to the persisted cart, and that it is hidden at 1024 px.
- UX10/UX12/UX13: buyer-facing empty and copy states were revised; Store cards show an existing public description when present. Shop, Search, Store directory and order history now have loading and retry states.
- UX14: menu and search dialogs trap Tab and return focus to their triggers on Escape. The browser navigation suite passed those checks. A full screen-reader audit was not performed.

**Browser journey:** a 390 px Chrome run traversed Home → Shop filter → Search → Product A → Product B → grouped Cart → grouped Checkout. The first Checkout response was aborted after the local server committed it. After refresh, two tabs submitted the same attempt: three POSTs total resulted in one Checkout, two vendor Orders and one decrement per Product. Both tabs reached the same receipt and refresh retained access. This verifies the local browser path, not production concurrency under load.

**Remaining UX issues:** all checkout customers must choose a garment size because the current API and Order schema require it, even for products outside clothing; changing that needs a reviewed data-model and business rule. Product/R2 images still use `unoptimized`; no representative R2 payloads or Cloudflare optimizer verification were available. Store-local categories remain intentionally scoped until the taxonomy decision. Wishlist, reviews, verified payment, refund tracking and delivery tracking do not exist. Some pages still use small text and inconsistent surfaces; a real screen-reader pass and real image-quality review remain open. The automated `scripts/audit-accessibility.mjs` axe scan of home/shop/stores/product at 390 and 1440 px reported zero WCAG 2.2 AA violations on these pages; this supplements, but does not replace, manual keyboard/screen-reader QA.
